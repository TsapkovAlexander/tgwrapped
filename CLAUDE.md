# tgwrapped

## Проект
Статический одностраничник: пользователь загружает JSON-экспорт личного чата Telegram, браузер сам считает статистику и рисует 8 вертикальных карточек 1080×1920 для сторис. Ни сервера, ни аккаунтов — файл не покидает устройство.
> Подробнее: `app/README.md`

## Стек
- Фронтенд: HTML/CSS/ES-модули, без сборки и без рантайм-зависимостей из npm
- `app/stats.js` — `analyze(export, {names})` разбирает `messages` экспорта Telegram Desktop и возвращает объект `S`
- `app/render.js` — `buildSlides(S)` (восемь `[класс, html]`) и `titles(S)` (правила вердикта)
- `app/share.js` — вывод наружу: PNG, альбом, лист, текстовый отчёт, ссылка с состоянием
- `app/format.js` — числа, время, склонение числительных
- `app/vendor/html2canvas.min.js` 1.4.1 — локально, единственная сторонняя библиотека
- Шрифты: локальные woff2 — Gluten (цифры), Nunito (текст), OFL
- Бэкенда и БД нет и не планируется

## Соглашения
Глобальные скиллы `nextjs-bff-conventions` и `supabase-schema` неприменимы: ни BFF, ни базы здесь нет. Специфика:
- Локаль UI: ru-RU. Бизнес-таймзоны нет намеренно: время сообщений считается в локальной таймзоне браузера — «когда мы писали» для пользователя значит его собственные часы
- Дизайн-система своя, светлый минимализм. Палитра `--ink #1F1D1B`, `--paper #FBFAF7`, `--cream #F4F0E8`, `--sky #E9EFF5`, `--peach #F7E8E1`, участники `--a #D9694F` и `--m #4C8BC9`. Объявлена дважды: в `site.css` (`:root`) и в `slide.css` (`.slide`) — карточка обязана быть самодостаточной, её рендерит html2canvas
- Типографика: цифры — Gluten, текст — Nunito. Gluten объявлен с `unicode-range` только на цифры, разделитель разрядов и процент: кириллицы в нём нет, а числа внутри фраз должны брать его автоматически. Не ставить Gluten на буквы и не убирать unicode-range — русский текст молча съедет на фолбэк
- Формат слайда фиксированный: 1080×1920, вёрстка в абсолютных px. На экране слайд ужимается `transform: scale(clientWidth/1080)` в `fit()`; перед экспортом трансформ снимается
- Пол участника из экспорта неизвестен, поэтому в текстах карточек не должно быть родовых форм: ярлыки вердикта — глаголы третьего лица («Говорит голосом»), а не прилагательные («Голосовой»). Тест на родовые окончания это стережёт
- Числа в тексте — только через `np()`/`plural()` из `format.js`. «933 дней» и «401 звонков» — брак
- Два словаря стоп-слов в `stats.js` и путать их нельзя: `STOP` (широкий) отсекает шум в частотных `top_words`, `CORE` (только служебные) — в `signature`. Слова-паразиты обязаны попадать в фирменные, иначе метрика теряет смысл
- Код намеренно плотный: однострочники, короткие имена. Новый код держать в том же стиле, существующий не «причёсывать»
- Никаких сетевых вызовов на пути анализа. Обещание «файл не покидает телефон» проверяется механически: при загрузке страницы и экспорте PNG внешних запросов быть не должно

## Gotchas
- Открывать `app/index.html` через `file://` бесполезно: `fetch('demo.json')` падает, демо-веер прячется, рельса карточек остаётся пустой. Нужен http-сервер (`npm run dev`)
- Репозиторий публичный: в `app/demo.json` не должно быть настоящей переписки. Витрина собирается из `scripts/make-fixture.mjs` — вымышленный чат, посчитанный настоящим анализатором
- `app/demo.json` — не экспорт Telegram, а готовый результат `analyze()`: он уходит прямо в `buildSlides(D)`, минуя анализатор. Меняете структуру `S` — пересоберите его: `npm run demo -- <путь к result.json>` (скрипт подменяет имена и цитаты; `--keep-quotes` оставляет настоящие). Руками поля не дописывать — разъедется с анализатором
- `\b` в JS считает границей слова только ASCII, поэтому `/\bя\b/` в кириллице не срабатывает НИКОГДА. Границы задаются хелперами `w()` / `pre()` в `stats.js` через явный класс `[^а-яa-z0-9]`. Любая новая регулярка по русскому слову — только через них, иначе метрика молча даст ноль
- Словарные метрики (`signature`, `top_words`, `vocab`) считаются по `proseOf()`: он отбрасывает пересланные сообщения целиком (чужой текст — не речь), вырезает ссылки, пропускает блоки кода и сообщения, похожие на код: реальные рабочие чаты полны логов, и без этого фильтра в «любимые слова» лезут `null` и `data`. Ключи словарей — `Object.create(null)`: слово `constructor` иначе вернёт функцию из прототипа
- «A» и «M» — не участники по порядку, а топ-2 по числу сообщений: `A` тот, кто написал больше. Не считать `A` владельцем чата
- Число карточек больше не константа: подвал печатает плейсхолдер `__N__`, а `buildSlides` подставляет реальное число последней строкой. Не вычисляйте номер из длины массива внутри шаблона — на момент сборки строки он ещё не известен. Тест «нумерация сквозная» поймает рассинхрон
- Экспорт подставляет карточки в DOM по одной (`withExportScope` в `main.js` → `prepare` в `share.js`). Держать в документе весь набор нельзя: html2canvas клонирует документ на каждый снимок, и десять карточек 1080×1920 замедляют его всемеро
- Размер листа для отправки считается под число карточек (`sheetScale`): сумма сторон ≤ 9800 px, иначе Telegram отправит документом, и площадь ≤ 13 Мп, иначе откажет canvas в Safari
- Время берётся из строки `m.date` через `new Date(...)`. Строка без таймзоны, парсится как локальное время читателя, а не автора экспорта. `date_unixtime` не используется
- Порядок `<link>` в `index.html` значим: `fonts.css` → `site.css` → `slide.css`
- Лендинг и результат — два `<main>` с атрибутом `hidden`, а не одна лента: `#landing` скрывается, `#result` показывается. В кадре ровно одна карточка, её номер — переменная `i` в `main.js`
- Пороги захардкожены и повторяются: разрыв разговора и «вопрос без ответа» — 4 часа (`4*3600`, три места), монолог — 1 час
- html2canvas рендерит карточку ~1 с: альбом из восьми — около 19 с, лист — около 17 с. Любая кнопка отправки обязана показывать прогресс в `#status`
- Размер картинки для Telegram: фотографией уходит только то, у чего сумма сторон ≤ 10 000 px. Поэтому лист — сетка 2×4 (1944×6912), а не полоса 1×8. Верхняя граница с другой стороны — площадь canvas в Safari, примерно 16,7 Мп
- Адрес для ссылки берётся из `SITE` (`share.js`): на localhost — из `<link rel=canonical>`, иначе ссылка в чужом чате ведёт в никуда. Значит `npm run site -- <origin>` нужно прогонять и для локальной работы, иначе отчёты будут звать на прошлый домен
- `navigator.share` требует свежий жест: между кликом и вызовом нельзя рисовать карточки (это секунды). Поэтому подготовка (`prepareAlbum`/`prepareSheet`) и отправка (`sendFiles`) разделены, а `sendFiles` вызывается прямо из обработчика клика
- Файлы уходят системным окном только на телефоне (`canShareFiles`): десктопный браузер передаёт приложению пути к временным файлам, и в чат вместо альбома приезжает список путей
- В ссылку уходит не весь слепок, а `slim()` + `pack()` из `share.js`: поля пишутся массивом без ключей, пары «А и М» — двумя элементами, списки режутся. Префикс `1` — этот формат, `z` — прежний (ссылки, разосланные раньше, должны открываться): `t.me/share/url` отвечает 400 на длинный адрес. Добавили поле, которое рисует карточка, — впишите его в `KEEP`, иначе у получателя будет пусто; тест «в ссылку кладётся всё, что нужно карточкам» это ловит
- Ссылка с результатом несёт статистику внутри адреса, то есть отправляет цифры в переписку. Это единственный канал из четырёх, который так делает, — предупреждение рядом с кнопкой убирать нельзя

## Workflow
- Локальный запуск: `npm run dev` → http://localhost:8000
- Тесты: `npm test` — 50 штук на `analyze()`, метрики, карточки и форматтеры (`node --test`, TZ=UTC)
- Перед выкаткой: `npm test && npm run version:check`
- Линт/билд: нет, собирать нечего — в браузер уходят те же файлы, что лежат в репозитории
- Деплой: TODO: прод не поднят. Домен `tgwrapped.ru` стоит в футере и на карточках, но никуда не ведёт. Выкатка — заливка каталога `app/` на любой статический хостинг
- Prod-версия после выката: `curl -s <адрес>/ | grep -o 'name="version" content="[^"]*"'`
- Сменили домен — сразу `npm run site -- https://новый.домен` и выкатить: `og:image` обязан быть абсолютным (Facebook и X относительный не принимают), а Telegram кэширует превью намертво — сбрасывается через @WebpageBot
